# Travel skills review — 2026-09-28

審查基準：`c89e973`（pull 後的 `main`）。範圍為 `.claude/skills/` 七個 skills、根目錄規則，以及現有旅行檔案／網站結構的相容性。以下是指令與資料流程的審查，未執行購票、發布或旅行事實查核。

## 發現

### P1 — 修改現有行程仍要求覆寫整份 metadata

位置：[trip-plan:273](../.claude/skills/trip-plan/SKILL.md#L273)，搭配同檔 69–74 行的修改既有行程分支。

修改模式最後仍走「完整覆蓋」範本；範本沒有既有釜山 metadata 的詳細航班、Pass、已訂住宿及網站連結。只改偏好就可能遺失這些資料。新建可用範本，續填／修改應局部合併，保留未知欄位。

Codex 版：`trip-plan` 與 `AGENTS.md` 明定局部更新，不重建已有 metadata。

### P1 — 缺少 metadata 被當成整個資料夾可刪除

位置：[trip-plan:82](../.claude/skills/trip-plan/SKILL.md#L82)。

「放棄、從頭建新行程」執行 `rm -rf $TRIP`，但 metadata 不存在不代表資料夾沒有機票、研究或使用者筆記；該指令也未引用變數或驗證路徑邊界。放棄規劃應保留內容、記錄狀態並建立新編號，實際刪除需是明確需求。

Codex 版：放棄標 `aborted`、驗證行程路徑、不刪除舊資料。

### P1 — 網頁產出與部署流程不符合這個 repo

位置：[travel-planner:514](../.claude/skills/travel-planner/SKILL.md#L514)，另見 479–506 行的輸出結構。

skill 宣稱已接 Cloudflare Pages，寫根目錄 `index.html` 並自動 commit／push。本 repo 實際發布 GitHub Pages 的 `docs/`，首頁是 `docs/index.html`，行程是 `window.TRIP` 資料。照做會產生網站找不到的輸出，也把「生成攻略」擴大成發布。

Codex 版：`travel-planner` 沿用既有 renderer、首頁索引與相對路徑；發布按使用者要求另行執行。

### P1 — 緊急卡流程作出不成立的個資保證

位置：[trip-pack:101](../.claude/skills/trip-pack/SKILL.md#L101)，以及 [.gitignore](../.gitignore)。

skill 說姓名、聯絡電話等「不會上傳任何伺服器」，接著寫入 repo 的 profile／緊急卡；`.gitignore` 只有 `.DS_Store`，無法支持此保證。後續 Git 提交或公開網站轉換可能帶出資料；輸入助手也不能描述成絕對僅本機。

Codex 版：一般清單不強迫個資，緊急卡預設空白欄位；個資版需私人位置，公開網站不得自動帶入。這次沒有修改使用者資料或 gitignore。

### P2 — 進度以檔案存在判定，且漏掉實際網站行程

位置：[trip:59](../.claude/skills/trip/SKILL.md#L59)，[trip-go:26](../.claude/skills/trip-go/SKILL.md#L26)。

任一 research Markdown（含空白清單、骨架）即被判為研究完成；`review.md` 即使仍有嚴重缺項也算已審查。排程僅認 `final-itinerary.md`／`overview.md`，因此現有釜山四天網站被判成「未排程」。`trip-go` 又要求 `research/index.md`，但目前有效研究用 `day1-seomyeon.md` 等檔案，沒有該索引。

Codex 版：依內容、缺項與版本評估，支援 metadata 指向的 `itinerary.js` 和現有研究檔名；清單產出與使用者辦妥分開。

### P2 — 派工上限互相矛盾，失敗處理可能不斷擴增工作

位置：[trip-research:37](../.claude/skills/trip-research/SKILL.md#L37)、[331](../.claude/skills/trip-research/SKILL.md#L331)、[354](../.claude/skills/trip-research/SKILL.md#L354)、[586](../.claude/skills/trip-research/SKILL.md#L586)。

前段硬上限十個，後段卻要求每輪十至十五個且示例一次十三個。失敗一律拆成更多 agent、直到全部完成，缺少有限的重試邊界；又把報告短視為配額不足，可能誤判登入牆或資料不存在。這些策略也綁定 Claude 訂閱及專用工具，無法直接移植 Codex。

Codex 版：預設直接研究，使用者要求才委派且遵守環境容量；按實際錯誤處理，查不到就記錄缺項。

### P2 — 舊版偵測仍會命中文件自身的範例

位置：[trip:44](../.claude/skills/trip/SKILL.md#L44)。

`grep -q '<!-- TRIP_METADATA_START -->' CLAUDE.md` 雖用了完整註解字串，根目錄 `CLAUDE.md` 的說明段落本身就包含相同字串。在沒有編號行程的分支中，正常文件可能被誤認成待搬遷的舊行程。必須辨識實際 metadata 區塊與配套資料，而不是 substring。

Codex 版：共用規則要求以實際內容佐證，不以字串單獨判斷。

### P2 — 固定門檻與欄位推論會產生錯誤的行前判斷

位置：[trip-review:47](../.claude/skills/trip-review/SKILL.md#L47)、[71](../.claude/skills/trip-review/SKILL.md#L71)、[trip-pack:44](../.claude/skills/trip-pack/SKILL.md#L44)。

轉機最短時間套用固定數字，時差從國籍／首都推算，護照效期與辦理天數寫成通用要求。這些都需要實際護照、出發地、承運人、轉機流程、旅行日期與官方規則；旅客可能住在國籍以外的國家。此處指出推論方法問題，並未對特定旅程的法規作結論。

Codex 版：動態查證並區分未確認項，不沿用固定六個月／通用 MCT 規則，也不以國籍推時區。
