# 完整旅遊攻略與手機行程網站 (travel-planner)

本技能負責將完整旅行攻略整合為結構化資料，或將排定之行程編譯為行動端友善的旅行手帳網頁（支援本專案之 GitHub Pages 與獨立離線 HTML 頁面）。

---

## 依工作情境選擇範圍

1. **情境 A：已有行程，要求「產出/更新網頁版」**：
   * 直接讀取該行程資料夾之 `trip-meta.md` 與 `final-itinerary.md`，不重複進行前置訪談或重新研究。
   * 將行程資料轉譯為網頁格式並更新。
2. **情境 B：全新要求「製作完整旅遊攻略」**：
   * 循序串接流程：
     1. [trip-plan](../trip-plan/SKILL.md) 收集基本條件與建立畫像
     2. [trip-research](../trip-research/SKILL.md) 進行深度事實驗證
     3. [trip-go](../trip-go/SKILL.md) 排定每日時間表與交通動線
     4. [trip-review](../trip-review/SKILL.md) 自動審查可行性與防呆
     5. 依要求產出對應網頁版或 Markdown 攻略全集
3. **情境 C：微調某日行程**：
   * 僅局部修改對應天數之時間軸或店家，最小範圍更新，不重新生成整站。

## 網頁生成與 GitHub Pages 規範（適用本專案）

本專案之公開旅行手帳發布於 GitHub Pages 的 `docs/` 目錄：

### 1. 資料夾與檔案結構
* 每一趟旅行在 `docs/` 下有獨立目錄，格式為 `docs/{地點代碼}-{YYYY-MM}/`（例如 `docs/sin-2026-10/`、`docs/pus-2026-11/`）：
  * `index.html`：頁面結構、樣式與渲染邏輯。
  * `itinerary.js`：行程核心資料（改行程只改此檔案）。
* 根目錄手帳首頁：`docs/index.html`，透過其中的 `TRIPS` 陣列維護旅行清單與印章色彩。
* 共用樣式：`docs/assets/journal.css`（維持手帳風格、印章與紙膠帶質感）。

### 2. 建立新旅行網頁步驟
1. **複製範本**：
   * 一般與台灣無時差地區：複製 `docs/sin-2026-10/`。
   * 需跨時區、換算時差或搭乘長程航班地區：複製 `docs/pus-2026-11/`（具備 `utc`、`flight`、`eve` 等時區處理邏輯）。
2. **更新設定**：
   * 逐項替換地名、日期、時區（`timeZone`）、標題、票根說明與地圖導航網址。
   * 韓國地區使用 Naver Map 連結；其他國家替換為 Google Maps。
3. **編寫 `itinerary.js`**：
   * 遵守 `window.TRIP` 格式（包含 `title`、`subtitle`、`dates`、`days`、`items`、`places` 等）。
   * 每日紙膠帶色彩依據 `line` 屬性（如 `cc` 芥末黃、`ne` 乾燥玫瑰、`ew` 鼠尾草綠）。
4. **首頁索引維護**：
   * 於 `docs/index.html` 的 `TRIPS` 陣列最上方新增此趟旅行紀錄。
   * 同步更新根目錄 `README.md` 的行程表格。

### 3. 個資與公共安全規範（重要）
* `docs/` 屬於公開 GitHub Pages 靜態站點。
* **嚴禁**將使用者的護照號碼、真實身分證號、機票訂位代碼（PNR）、私人住家/手機電話或保險詳細單號自動寫入 `docs/` 或公開 script 中。
* 僅保留旅遊景點、大眾交通班次、餐廳名稱與公開觀光資訊。

### 4. 驗證與交付
1. **語法檢查**：修改 `itinerary.js` 後，可用 `node --check itinerary.js` 驗證 JavaScript 語法。
2. **本機預覽**：使用本機 HTTP 伺服器預覽確認手機寬度、深色模式、PWA 快取與離線閱讀表現。
3. **交付宣告**：清楚區分「本機變更完成」與「已發布上線」；僅在使用者明確要求 commit / push 時才進行 Git 操作。

## 獨立離線 HTML 模式（適用非專案或單一檔案分享）

若在非本專案環境或使用者明確要求「給我一個可以單檔傳給朋友看的 HTML」：
1. 產出單一完整 HTML 檔於行程資料夾（`./$TRIP/{目的地}-旅行手帳.html`）。
2. 內嵌所有 CSS 樣式，支援響應式手機排版、深色模式切換與地圖直接跳轉。
3. 不依賴外部未授權之特定 CLI 或付費服務，直接以原生 HTML+CSS 提供閱讀體驗。
