# 編排每日行程

遵循 repo 根目錄 `AGENTS.md`。先讀 metadata、畫像、相關研究與現有行程；不因缺少研究索引或 Markdown 而要求重建。

## 編排

- 先固定已訂航班、住宿、預約與使用者必去項，再依地理位置串聯。使用者排除的項目不得自行加回。
- 交通估算包含走路、候車、搭乘、轉乘、出站與合理緩衝；缺乏當日班次時明列估算，不把預設分鐘數當查證結果。
- 使用實際城市時區及旅行日期處理跨日、夜班、夏令時間。起飛和落地各用當地時間，計算飛行時長先換成同一時基。
- 查營業／休館、最後入場、Pass 啟用到期與預約規則；日出、日落、特殊活動有需求才查對應日期。
- 根據體力、同行者及偏好調整密度，安排用餐、休息與雨備；不以國籍推斷出發地或疲勞程度。
- 保存已確認的餐廳分店、當地名稱／地址與適用地圖連結；找不到座標時不要猜。

## 寫入與同步

1. 使用者指定網頁／某天網站行程時，直接更新該趟 `itinerary.js`；只改相關資料，保留 renderer 與其他日期。
2. 新的文字行程依本趟 metadata 設定寫 `final-itinerary.md`，或 `overview.md` + `day-N.md`。格式設定不存在時預設單檔；不得覆蓋其他格式的手動內容。
3. 每天包含日期與星期、當日路線、時間／活動／門到門交通／費用、備案、待確認事項及支持關鍵數字的來源。不確定項不能偽裝已訂。
4. 預算保留原幣別，區分每人／全團、單次／每日、已付／預估；核對小計與總計。換算需附匯率來源與日期。
5. 原有記帳檔只局部更新預估，不重置實際支出。使用者需要記帳時才建立 `expense-log.md`；實際未知留空，別填零當已支出。費用語句需明確是記帳要求，含糊幣別／分攤方式再問。
6. 更新 metadata 的檔案連結與受影響條件。同時存在 Markdown 與網站時，在本次授權範圍內同步同一事實；未同步的衍生版本須明列，不能宣稱自動同步。

檢查星期、時間衝突、日期覆蓋、預算及變更範圍。已有 `review.md` 或清單時標記受影響項需重查，保留歷史結論。交付簡短每日總覽、改動與未定項；網頁工作讀 [travel-planner](../travel-planner/SKILL.md)。
