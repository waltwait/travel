# 目的地研究

遵循 repo 根目錄 `AGENTS.md`，先讀選定行程的 metadata、畫像及相關既有報告。不要求先有 `research/index.md`，也不限定報告必須叫 `agent-*.md`。

## 研究範圍

- 依本次要求列必要研究項目。只問某天交通就研究那段，不擴張成整趟旅行調查。
- 全面研究才建立／更新 `research/research-checklist.md`，涵蓋使用者核心興趣、動線、票券、住宿需求與必要行政資訊。已訂機票／住宿不重新推薦替代品，但仍查相關轉乘、入住與寄放行李條件。
- 釜山等有城市 Pass 的行程，要查適用項目、啟用與到期規則、預約及休館日；不能只看景點名稱就認定免費。
- 入境查核需知道持用護照與實際路線；缺失時先問，同時可繼續獨立的景點研究。

## 查證與保存

1. 使用可用的網路搜尋與官方頁面，保留結論、原始 URL、查詢日期、適用日期。營業時間、票價、班次、保險／簽證規則以相關官方來源為主。
2. 社群與部落格可用於發掘體驗與近期口碑；登入牆或搜尋摘要不能宣稱已讀全文。搜尋連結只是探索入口，不等於支持事實的來源。
3. 資料衝突時比較更新日期、適用分店、旅遊日期與規則適用範圍，不能只取較新文章。查不到就列具體未知與影響，不捏造數字。
4. 依主題更新 `research/{topic}.md` 或延續已有檔名；逐段保存已確認成果，保留使用者註記。報告包括範圍、建議、證據、估算／待確認事項及來源。
5. 同一來源連續無法取得時改查其他可靠來源；無新線索就保留缺項。只有明確的工具限額錯誤才歸因配額，不以短報告推測。
6. 完成度按項目是否得到有來源的可用答案評估，不以 H2 數、TODO 數或 URL 距離計分。區分已確認、部分完成、待確認、不適用；不把「無可靠資料」算完成。

預設直接在主執行緒研究，不詢問 Claude 訂閱方案。使用者要求平行研究且環境可用時，依實際並行容量派獨立主題、分開報告路徑，由主執行緒整合；不讓多個執行者同時覆寫清單或 metadata。

## 續跑與交付

- 讀既有清單、報告與 `dispatch-plan.md`（若有），只補缺項及需要更新的資訊。舊派工紀錄不代表背景工作仍在執行。
- 多份報告時可更新 `research/index.md` 作索引；它不是下游工作的必要門檻。
- 回覆最影響安排的結論、查不到的關鍵項與保存位置。使用者要求完整安排時接 [trip-go](../trip-go/SKILL.md)，把未確認依賴標清楚。
