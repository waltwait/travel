# 行程品質審查

遵循 repo 根目錄 `AGENTS.md`。讀選定旅行的 metadata、偏好、實際行程（Markdown 或網站 JS）與相關研究。只有部分行程時仍可審查已有內容，清楚界定範圍。

## 依實際行程檢查

- 日期／星期、跨日、出發地及抵達地時區、航班時長與夏令時間。
- 景點／餐廳的城市、分店、地址，預約／營業／最後入場／休館及旅行日期是否相符。
- 門到門移動、轉乘、末班車、寄放行李與機場報到時間。查實際航空公司與機場規定，不把一般緩衝建議標為官方 MCT。
- 同日活動時間重疊、跨區折返、用餐／休息與體力需求，已訂與必去項是否保留。
- 票券有效期、Pass 首次啟用、預約／額外收費；兒童票依年齡與業者規則。
- 費用的幣別、人數、單價／總價、已付／預估、每日小計與全程總計。
- 影響該趟旅行的入境／轉機、假日、停駛與施工；有需要時查電器標籤／出發地資訊，不能用國籍代替。
- 研究與行程是否矛盾、關鍵事實來源是否支持結論、清單及網頁是否落後。

動態或重要未知需查最新適用來源；查不到記為待確認。依風險與範圍決定查證數，不用固定八項上限卻宣稱所有檢查通過。不適用項標 N/A，未查證項不算通過。

## 修正與報告

1. 每個問題附具體日期／時段／檔案位置、影響、證據或重算結果、建議修正。
2. 分成嚴重（會趕不上／無法入場）、一般（動線／預算／體驗）、輕微（格式／連結）。沒問題不硬湊數。
3. 使用者只要 review 時輸出報告與建議，不默認改動行程。已要求「檢查並修正」才修正可判定項；重大行程取捨缺少偏好時提出具體選項。既有訂單不能當成可取消的普通草稿。
4. 在該趟 `review.md` 記錄審查日期、範圍、行程版本（如內容摘要／雜湊）、問題、已修正／待決／未查證項及來源；重跑時保留必要的前次紀錄。
5. 若修正了行程，重查受影響的後續時段與總費用。使用者未實際預訂的項目不得標「已完成」。

交付優先列最會影響旅行的問題與限制，接著列已做修正。通過結論只涵蓋實際檢查的範圍。
