# 旅行進度總管

遵循 repo 根目錄 `AGENTS.md` 的行程解析、資料保留與網站規則。

1. 依使用者指定或 `current-trip` 找到行程，讀 `trip-meta.md` 與相關檔案。要求新增或切換時直接處理該意圖，別被舊指標攔住。
2. 判定各階段的實際內容，而非僅檔案是否存在：
   - 規劃：目的地、日期／待定範圍、同行者與必要偏好是否足以工作。
   - 研究：讀研究清單與報告；空檔、待補骨架、不可靠來源仍是未完成或部分完成。沒有清單也可依報告內容評估。
   - 排程：讀 Markdown 或 metadata 指向的網站 `itinerary.js`；確認涵蓋旅行日期，區分已有安排與空白待排。
   - 審查：讀 `review.md` 的問題、待確認項、審查版本；有未解決嚴重問題或行程已變更，不能標為全數通過。
   - 行前準備：區分「清單已產出」與「使用者已完成準備」。未勾選項不得顯示已完成。
3. 用目的地、日期、一行進度和最重要缺項回覆。`aborted` 行程不自行復活或刪除；依本次明確續用／新建要求處理。
4. 使用者只問進度時回報即可；說「繼續」或明確要求工作時，讀取下面對應 skill 並完成已授權階段，不逐步要求再確認。真正缺少選擇時才問。

| 意圖／所需工作 | 讀取的 skill |
| --- | --- |
| 新增行程、調整基本條件 | [trip-plan](../trip-plan/SKILL.md) |
| 補研究資料 | [trip-research](../trip-research/SKILL.md) |
| 編排／修改每日行程 | [trip-go](../trip-go/SKILL.md) |
| 檢查可行性與錯誤 | [trip-review](../trip-review/SKILL.md) |
| 行前準備、打包 | [trip-pack](../trip-pack/SKILL.md) |
| 網頁版或完整旅行攻略 | [travel-planner](../travel-planner/SKILL.md) |

沒有 metadata、但已有使用者指定的網站行程時，可直接讀它回答；只在需要持久化規劃設定時補建 metadata，不強迫重跑全部流程。
